# Руководитель, лента наставника и подробности задач: что нужно от backend

Фронт уже работает на моках: колокольчик и согласования – в `frontend/src/mocks/leadData.ts` (они в `pendingHandlers`, поэтому перехватываются и при живом backend), цели – в `frontend/src/mocks/goalsData.ts` (только полный режим без backend). Когда ручка готова, удалите ее обработчик из `leadHandlers`.

## 1. Роли и разделы

- Руководитель (`lead`) видит только два раздела: «Цели стажеров» (`/`) и «Согласования» (`/approvals`). Остальные разделы кабинета наставника ему не показываются.
- `GET /api/interns` для руководителя – все стажеры его команды (как сейчас).

## 2. Цели: шаги при создании и изменении

`POST /api/interns/{internId}/goals` и `PATCH /api/goals/{goalId}` теперь могут прийти с полем `steps`:

```json
{
  "title": "Пройти путь задачи до релиза",
  "criterion": "первый merge в main до 6 недели",
  "dueWeek": 6,
  "okrId": "f200…0001",
  "steps": [
    { "title": "Доступ к GitLab", "source": "task" },
    { "title": "Merge в main", "source": "mentor" }
  ]
}
```

- `source`: `task` | `mentor` | `lead`, до 8 шагов, `title` до 120 символов.
- В PATCH список шагов заменяется целиком. Нет поля `steps` – шаги не трогаем.
- Шаг `task` без `taskId` – можно оставить `task_id = null`, тогда шаг считается невыполненным, пока наставник не привяжет задачу (или сопоставить по названию с задачей плана – на ваше усмотрение).
- Уже есть и используется: `POST /api/interns/{id}/goals/agree` (только руководитель) и `POST /api/goals/{goalId}/steps/{stepId}` `{ "done": true }`.
- `canAgree = true` только руководителю, пока цели не согласованы и есть хотя бы одна цель.

## 3. Согласования руководителя

Заявки стажеров, где пользователь – согласующий (заявки на доступ из чата AI-buddy, отгулы).

| Метод | Путь                  | Тело                                                                                    | Ответ                                                          |
| ----- | --------------------- | --------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| GET   | `/api/approvals`      | –                                                                                       | `Approval[]`, сначала `waiting`, затем по убыванию `createdAt` |
| POST  | `/api/approvals/{id}` | `{ "decision": "approve" }` или `{ "decision": "reject", "reason": "до 300 символов" }` | `Approval`                                                     |

```json
{
  "id": "uuid",
  "number": "1042",
  "internId": "uuid",
  "internName": "Анна",
  "title": "Доступ к GitLab",
  "fields": [
    { "label": "Проект", "value": "backend/auth-service" },
    { "label": "Уровень прав", "value": "Developer" }
  ],
  "createdAt": "2026-11-12T10:20:00+03:00",
  "status": "waiting",
  "rejectReason": null
}
```

- `status`: `waiting` | `approved` | `rejected`. `fields` – те же поля, что в карточке заявки у стажера.
- Отказ без причины – 400 `validation_error`. Повторное решение – 409 `conflict`. Чужая заявка – 404, стажер – 403.
- После решения: статус заявки у стажера («Мои заявки») меняется, задача плана с этой заявкой закрывается при `approved`, стажеру уходит уведомление. Это же событие попадает в ленту наставника.

## 4. Лента наставника (колокольчик)

| Метод | Путь                    | Ответ                                                                 |
| ----- | ----------------------- | --------------------------------------------------------------------- |
| GET   | `/api/mentor/feed`      | `{ "items": FeedItem[], "unread": 3 }`, последние 20 по убыванию `at` |
| POST  | `/api/mentor/feed/read` | 204, все записи прочитаны                                             |

```json
{
  "id": "uuid",
  "actor": { "name": "Олег", "kind": "lead" },
  "text": "Олег согласовал цели Анны",
  "at": "2026-11-12T10:05:00+03:00",
  "read": false
}
```

- `kind`: `intern` | `mentor` | `lead` | `buddy` | `other`.
- Что пишем в ленту: согласование целей, подтверждение шага руководителем, решение по заявке стажера, ответ стажера на приглашение («Приду» / «Попросить перенести»), закрытие задачи стажером, ответ AI-buddy со ссылкой на материал наставника. Можно брать из таблицы `notifications`.
- Стажеру – 403.

## 5. Подробности задачи у стажера

В `GET /api/path` (и `GET /api/interns/{id}/path`) у задачи новое необязательное поле:

```json
"details": { "about": "Без GitLab не получится взять первую задачу…",
             "helper": "AI-buddy заполнит заявку, согласует Олег",
             "doneWhen": "заявка согласована и ты видишь репозиторий",
             "goal": "Пройти путь задачи до релиза" }
```

- `about`, `helper`, `doneWhen` – новые колонки шаблона задачи (`task_templates`), их можно заполнить в seed и в редакторе плана.
- `goal` – название цели стажера, в шагах которой есть эта задача (`goal_steps.task_id`), иначе `null`.
- Нет поля или `details: null` – фронт покажет только `note` и срок.

## 7. Путь на всю стажировку (по чек-листу Авито)

- У этапа новое поле `period`: «неделя 1», «недели 1–2», «недели 2–4», «недели 4–8», «месяцы 1–2», «после 3 месяцев», «конец стажировки». Без поля фронт покажет `tip`.
- Новые задачи этапа 01: «Добавиться в чаты и каналы команды» (действие `join_chats`) и «Завести конспект встреч с наставником».
- Новые этапы в seed шаблона: 05 «Безопасность и учеба» (материалы по защите данных – действие `ask_buddy` с `payload.prompt`; памятка о практике), 06 «Экватор» (мастер-классы, презентация – `ask_buddy`, согласование с куратором, выступление), 07 «Итоги» (1:1 по итогам, выпускной, опрос). Тексты и сроки – в `frontend/src/mocks/pathData.ts`.
- Новое действие `join_chats`: помощник показывает карточку подтверждения «Добавить в чаты и каналы?» (поля «Чаты», «Каналы», «Закрытые»), после подтверждения заявка сразу `done`, задача `t-104` закрывается, в результате `status: "done"` – фронт пишет «Готово».
- У `ask_buddy` в `payload.prompt` – готовый текст запроса, фронт подставляет его в чат.

## 8. Чек-лист наставника

| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| GET | `/api/mentor/interns/{internId}/checklist` | – | `{ internId, items: [{ id, title, hint, fromWeek, period, done }] }` |
| POST | `/api/mentor/interns/{internId}/checklist/{itemId}` | `{ "done": true \| false }` | тот же ответ |

Пункты одни на команду (10 штук, список – в `frontend/src/mocks/leadData.ts`, `TEMPLATE`), отметки хранятся на пару наставник–стажер. `fromWeek` – с какой недели пункт актуален; фронт показывает пункты до следующей недели стажера. Стажеру – 403.

## 9. Конспект встреч стажера

| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| GET | `/api/me/notes` | – | `[{ eventId, text, updatedAt }]` |
| PUT | `/api/me/notes/{eventId}` | `{ "text": "до 4000 символов" }` | `{ eventId, text, updatedAt }`, пустой текст удаляет |

Заметки видит только сам стажер. `eventId` – id события календаря (`meetings.id`).

## 10. Цели и компетенции, материалы и разделы

- У цели новое поле `competency` (строка или `null`), например «Код и ревью · L1», «Обмен знаниями». Принимается в POST/PATCH целей. Список вариантов – `COMPETENCIES` в `frontend/src/schemas/goals.ts` (по матрице компетенций AvitoTech Playbook).
- У материала новое поле `section` – раздел справочника. В `POST /api/materials` приходит `section` (название существующего раздела или новое – тогда раздел создается). Материалы с `useInAi` появляются в `GET /api/kb` в этом разделе.
- У наставника «Материалы» и «Справочник» объединены в один раздел; отдельный пункт «Справочник» в его меню убран.
- Автоматизации AI-buddy переехали из «Плана адаптации» в «Профиль и настройки» наставника, ручки те же.

## 11. Метрики пользы для наставника

`GET /api/mentor/metrics` (наставник и руководитель, стажеру 403). Считается за последние 7 дней по стажерам наставника.

```json
{
  "answeredByBuddy": 14,
  "escalated": 3,
  "hoursSaved": 2.8,
  "minutesPerQuestion": 12,
  "accessHours": 6,
  "onTimePercent": 82
}
```

- `answeredByBuddy` – вопросы стажеров, на которые ответил AI-buddy и стажер не переспросил наставника в течение дня.
- `escalated` – вопросы, переданные наставнику.
- `hoursSaved` – `answeredByBuddy × minutesPerQuestion / 60`; `minutesPerQuestion` – константа 12 (можно вынести в настройки).
- `accessHours` – среднее время от создания заявки на доступ до статуса «выдан», в часах; null, если заявок не было.
- `onTimePercent` – доля задач стажеров, закрытых не позже срока; null, если задач со сроком не было.

Фронт показывает это одной строкой на главной наставника, подробности по клику. Пока маршрута нет, отвечают демо-данные.
