# Подключение языковой модели к AI-buddy

Без ключа AI-buddy работает в офлайн-режиме (`LLM_PROVIDER=mock`): намерение определяется по ключевым словам, ответ берется из найденного фрагмента справочника. Весь сценарий с правами, подтверждением и заявками при этом работает. Модель нужна, чтобы помощник понимал свободные формулировки и отвечал своими словами по найденным статьям.

## Что требуется от модели

Backend обращается к модели по OpenAI-совместимому API (`POST {LLM_BASE_URL}/chat/completions`) и передает список инструментов (function calling). Модель выбирает инструмент: поиск по справочнику, заявку на доступ, отгул, статус заявок или передачу вопроса наставнику. Права и создание заявки проверяет backend, а не модель. Поэтому подходит любая модель, которая:

- доступна по OpenAI-совместимому API;
- поддерживает `tools` в Chat Completions;
- хорошо понимает русский язык;
- работает без GPU на стороне проверки (организаторы предупредили, что GPU не будет).

## Сравнение вариантов (ноябрь 2026)

| Вариант | Модели | Function calling | Бесплатно | Оплата из России | Вывод |
|---|---|---|---|---|---|
| Yandex AI Studio | YandexGPT Pro 5.1, Qwen3-235B, DeepSeek и другие | да, в Chat Completions (`tool_choice` только `auto` или `none`) | стартовый грант 4000 ₽ на 60 дней при регистрации с картой | да | основной вариант |
| Cloud.ru Foundation Models | GigaChat 3.x, Qwen3, DeepSeek V4, GLM и другие | зависит от модели, смотреть карточку в каталоге | нет, оплата за токены | да | запасной вариант, сюда же теперь направляют новых клиентов GigaChat |
| GigaChat API напрямую | GigaChat Lite, Pro, Max, Ultra | да | freemium для физлиц, но новых клиентов с 1 сентября 2026 направляют на cloud.ru | да | не подходит без доработки: токен живет 30 минут, нужен обмен ключа на токен |
| A-Vibe (Авито) локально | A-Vibe 8B, открытые веса, Apache-2.0 | модель обучена вызывать функции | да | не нужна | для демонстрации модели Авито; без GPU отвечает медленно |
| OpenRouter | сотни моделей | да | 50 запросов в сутки | с мая 2026 пополнение для российских аккаунтов закрыто | не рекомендуется |

Рекомендация: для разработки и демо взять Yandex AI Studio с моделью YandexGPT. Хорошее качество на русском, официальная совместимость с OpenAI, вызов функций, оплата российской картой, грант на старт. На защите можно показать, что смена провайдера – это три строки в `.env`. В том числе это относится к A-Vibe: организаторы подтвердили, что она OpenAI-совместимая.

Для проверки жюри свой ключ передавать не нужно: организаторы подключат собственный. В README указаны провайдер и переменные окружения.

## Вариант 1. Yandex AI Studio (рекомендуется)

1. Войдите в Яндекс ID и откройте консоль https://console.yandex.cloud. Если облака еще нет, консоль предложит создать облако и каталог `default`.
2. Создайте платежный аккаунт (личный) и привяжите банковскую карту сразу при создании аккаунта. Только в этом случае начисляется стартовый грант 4000 ₽ на 60 дней. Если привязать карту позже, гранта не будет. Пока действует грант, расходы оплачиваются из него.
3. Скопируйте ID каталога: в консоли откройте каталог, ID вида `b1g…` показан рядом с названием. Он понадобится дважды.
4. Откройте Yandex AI Studio (https://aistudio.yandex.ru), выберите тот же каталог и нажмите «Создать API-ключ» в правом верхнем углу. Выберите срок действия и нажмите «Создать». Сервисный аккаунт с нужными ролями создается автоматически. Для этого у вас должна быть роль `resource-manager.admin` на каталог; у владельца облака она есть.
5. Сохраните секретный ключ сразу. После закрытия окна он больше не показывается.
6. В корне проекта создайте `.env` из `.env.example` и заполните:

```
LLM_PROVIDER=openai_compat
LLM_BASE_URL=https://llm.api.cloud.yandex.net/v1
LLM_API_KEY=<секретный ключ>
LLM_MODEL=gpt://<ID_каталога>/yandexgpt/latest
LLM_PROJECT=<ID_каталога>
LLM_TIMEOUT=20s
```

Вместо `yandexgpt/latest` можно указать `yandexgpt/rc`: в ветке RC у YandexGPT Pro 5-го поколения улучшен вызов функций. Список доступных моделей возвращает `GET https://llm.api.cloud.yandex.net/v1/models` с теми же заголовками.

7. Перезапустите backend: `docker compose up -d backend`. В логе должна появиться строка `assistant ready` с `"llm":"openai_compat"`.
8. Проверьте модель напрямую (PowerShell):

```powershell
$h = @{ Authorization = "Bearer <ключ>"; "OpenAI-Project" = "<ID_каталога>" }
$b = '{"model":"gpt://<ID_каталога>/yandexgpt/latest","messages":[{"role":"user","content":"Привет"}]}'
Invoke-RestMethod -Method Post -Uri https://llm.api.cloud.yandex.net/v1/chat/completions -Headers $h -ContentType "application/json; charset=utf-8" -Body ([Text.Encoding]::UTF8.GetBytes($b))
```

9. В интерфейсе войдите как `intern_anna` и спросите в чате что-нибудь свободной формулировкой, например «кто посмотрит мой код перед релизом?». Ответ придет со ссылкой на статью «Как устроено код-ревью в команде».

## Вариант 2. Cloud.ru Foundation Models

1. Зарегистрируйтесь на https://cloud.ru и войдите в консоль платформы Evolution.
2. Пополните баланс: доступ к моделям платный, в среднем десятки рублей за миллион токенов. Демо хакатона расходует немного.
3. Создайте сервисный аккаунт и на вкладке «API-ключи» нажмите «Создать API-ключ». Сохраните ключ.
4. Откройте Evolution → AI Factory → Foundation Models, выберите модель (например, из линейки GigaChat или Qwen3) и нажмите «Использовать». В карточке будут адрес API и точное имя модели. Убедитесь, что в карточке указана поддержка вызова функций (tools).
5. Заполните `.env`:

```
LLM_PROVIDER=openai_compat
LLM_BASE_URL=https://foundation-models.api.cloud.ru/v1
LLM_API_KEY=<ключ>
LLM_MODEL=<имя модели из карточки>
LLM_PROJECT=
```

6. `docker compose up -d backend` и проверка в чате, как в варианте 1.

## Вариант 3. A-Vibe локально через Ollama

A-Vibe – модель Авито на базе Qwen3-8B с открытыми весами. Публичного API у нее нет, но ее можно запустить у себя. Без GPU модель на 8 млрд параметров отвечает за десятки секунд, поэтому вариант подходит для демонстрации, а не для основной работы.

1. Установите Ollama для Windows с https://ollama.com.
2. Скачайте сжатую версию модели (около 5 ГБ, нужно 8 ГБ свободной памяти):

```powershell
ollama pull hf.co/NightForger/avibe-GGUF:Q4_K_M
```

3. Заполните `.env` (адрес `host.docker.internal` ведет из контейнера на ваш компьютер):

```
LLM_PROVIDER=openai_compat
LLM_BASE_URL=http://host.docker.internal:11434/v1
LLM_API_KEY=ollama
LLM_MODEL=hf.co/NightForger/avibe-GGUF:Q4_K_M
LLM_TIMEOUT=90s
```

4. `docker compose up -d backend`.

Вызов функций через Ollama зависит от шаблона чата в сжатой версии модели. Если модель отвечает текстом и не вызывает инструменты, AI-buddy все равно работает: такой ответ показывается как есть, а заявки можно оформлять кнопками «Сделать с AI-buddy» на «Моем пути», где действие известно заранее. С GPU надежнее запуск через vLLM: `vllm serve AvitoTech/avibe` и `LLM_BASE_URL=http://host.docker.internal:8000/v1`.

## Безопасность ключа

- Ключ хранится только в `.env`. Этот файл уже в `.gitignore` и не попадает в репозиторий.
- Ключ не нужен фронту: модель вызывает только backend.
- Если ключ случайно попал в git, удалите его в консоли провайдера и создайте новый.

## Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| backend не стартует, в логе `LLM_BASE_URL and LLM_MODEL are required` | для `openai_compat` не заполнены адрес или модель |
| в чате ответы как раньше, в логе `llm failed, using offline answer` | модель не ответила: проверьте ключ, адрес, ID каталога (`LLM_PROJECT` для Яндекса) и запрос из шага 8 |
| `status 401` или `403` | неверный ключ или у сервисного аккаунта нет роли на каталог |
| `status 429` | превышена квота запросов, подождите или уменьшите частоту |
| ответы долгие | увеличьте `LLM_TIMEOUT`; для локальной модели это нормально |

Каждый вызов модели записывается в таблицу `agent_tool_calls`: время ответа, статус (`ok`, `error`, `timeout`). По ней удобно сравнивать провайдеров.
