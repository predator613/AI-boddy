# Обращения в поддержку: что нужно от бэка

Зачем: на странице «Поддержка» есть форма «Сообщить о проблеме» у стажера, наставника и руководителя. Сейчас она ничего не отправляет, только показывает «Спасибо». Нужны два маршрута, после этого фронт покажет номер обращения и список «Мои обращения».

## 1. Создать обращение

`POST /api/support/tickets` (любая роль, по токену)

```json
{
  "type": "Не согласуется заявка",
  "details": "Нажимаю «Согласовать», ничего не происходит",
  "internId": "uuid или null",
  "attachDialog": true
}
```

- `type` – строка из списка на фронте (списки разные для стажера, наставника и руководителя, бэку достаточно хранить текст).
- `details` – обязательное, до 2000 символов.
- `internId` – про какого стажера обращение, только у наставника и руководителя, можно null.
- `attachDialog` – приложить последний диалог с AI-buddy (у руководителя этого флажка нет, придет false).

Ответ 201:

```json
{ "id": "uuid", "number": "SUP-1042", "status": "new", "createdAt": "2026-11-13T15:00:00+03:00" }
```

Ошибки: 400 validation_error с текстом, как в остальных маршрутах.

## 2. Мои обращения

`GET /api/support/tickets` – обращения текущего пользователя, новые сверху.

```json
[
  {
    "id": "uuid",
    "number": "SUP-1042",
    "type": "Не согласуется заявка",
    "details": "…",
    "status": "new",
    "createdAt": "2026-11-13T15:00:00+03:00",
    "answer": null
  }
]
```

`status`: new (принято), in_progress (в работе), done (решено). `answer` – текст ответа поддержки или null.

## 3. Куда уходит обращение

Так же, как заявки на доступ: через адаптер во внешний сервис. В демо это mock-services (тот же «Jira Service Desk», очередь SUP), номер берется оттуда. Для демо достаточно, чтобы имитация через DecisionDelay переводила обращение в in_progress, а потом в done с ответом «Исправили, проверь, пожалуйста».

## 4. Что сделает фронт, когда маршруты появятся

- После отправки покажет «Обращение SUP-1042 принято».
- Под формой добавит сворачиваемый список «Мои обращения» со статусами.
