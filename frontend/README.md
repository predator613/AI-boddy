# AI-buddy – frontend

React 19 + TypeScript, TanStack Router и Query, Zustand, Zod, Mantine. Шрифты Onest и Caveat, иконки Tabler. Тесты – Vitest и Testing Library, моки запросов – MSW.

Интерфейс рассчитан на ноутбук и компьютер: это основные рабочие инструменты стажера и наставника.

## Локальный запуск

Проще всего запускать все вместе через Docker из корня проекта: `docker compose up --build -d`, интерфейс на http://localhost:3000.

Без Docker:

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173, нужен backend: docker compose up -d backend mock-services
npm run dev:mock   # без backend: все запросы обрабатывают моки MSW, данные синтетические
```

## Как фронт работает с backend

- Все запросы идут через один модуль `src/api/client.ts` (`apiFetch` / `apiRequest`); каждый ответ проверяется Zod-схемой из `src/schemas`.
- При работе с backend все данные приходят с backend. Моки MSW включаются только в режиме `dev:mock` и в тестах.
- Корпоративные сервисы (Jira Service Desk, отделы) имитирует контейнер `mock-services`. Фронт видит их через backend: ключ заявки, статус и ссылку на страницу заявки.
- Ошибки сервера показываются текстом из ответа, 401 разлогинивает, долгие ответы AI-buddy не блокируют интерфейс (индикатор «печатает»).
- Настройки (`settingsStore`) хранятся в браузере отдельно для каждого аккаунта.

Контракты API для backend: `docs/api-*.md`, что готово на backend – `docs/api-backend-status.md`.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | dev-сервер с горячей перезагрузкой |
| `npm run dev:mock` | dev-сервер на моках, backend не нужен |
| `npm run build` | проверка типов и сборка в `dist/` |
| `npm test` | тесты в режиме наблюдения |
| `npm run test:run` | тесты один раз |
| `npm run coverage` | тесты + отчет о покрытии в `coverage/` (порог 80% строк, сейчас около 95%) |
| `npm run lint` | проверка кода (oxlint) |
| `npm run format` | форматирование (Prettier) |

Тесты в Docker: `docker compose --profile test run --rm frontend-tests`.

## Структура

```
src/
├── api/          client.ts – единый клиент; запросы по разделам (path, assistant, goals, staff, support, ...)
├── schemas/      Zod-схемы ответов backend и форм
├── hooks/        хуки TanStack Query
├── store/        Zustand: authStore (токен), settingsStore (настройки по аккаунтам), toastStore, planLogStore
├── lib/          меню по ролям, права на маршруты, статусы и цвета, ключи Jira, время по Москве, ошибки
├── components/   AppRail (меню), Mascot (5 состояний), path/* (путь стажера), chat/*, mentor/*
├── pages/        экраны
├── routes/       маршруты TanStack Router (file-based), проверка роли в beforeLoad
├── content/      статичные тексты (поддержка)
├── mocks/        MSW для режима без backend и тестов
├── styles/       анимации и общие стили
└── theme.ts      тема Mantine: палитра и шрифты
tests/            тесты Vitest: экраны по ролям, сценарии чата и заявок, права доступа
```

## Переменные окружения

См. `.env.example`: `VITE_API_URL` – адрес backend, `VITE_USE_MOCKS=true` – работать только на моках.
